The information architecture, page structure, copy, quote builder logic, forms, routes, and SEO structure are proven and stay. ## THE BRAND YOU ARE BUILDING

Orenara supplies IP68 outdoor LED strip lighting systems, made to order, for Australian conditions. The brand voice is **earned authority** — quiet superiority built on years of doing the basics right. Think: the best tradesman in the region, whose van is plain, whose name is set in clean type, who states facts and lets the work speak. Never salesy. Never decorative. Never loud.

Design translation:
- **Restraint is the flex.** Only established brands can afford to be this quiet.
- **The photography is the colour.** The UI is monochrome; warm light in imagery provides all warmth.
- **Spec data is treated like a compliance plate** — etched, precise, monospaced.
- If a design decision feels "premium" because it adds something (a glow, a gradient, an animation), it is wrong. Premium here is achieved by removing things and perfecting spacing.

## PHASE 2 — DESIGN TOKEN SYSTEM (replace wholesale)

Strip the existing colour/typography theme and implement exactly this. Every colour and type decision on the site must resolve to these tokens. No inline one-off values.

### Colour tokens

```
--ink:            #0F1113;   /* page background — deep warm charcoal, near-black */
--ink-raised:     #17191C;   /* cards, panels, form fields */
--ink-line:       rgba(243, 238, 228, 0.14);  /* hairlines, borders, dividers */
--bone:           #F3EEE4;   /* primary text — warm off-white, never pure #FFF */
--bone-dim:       rgba(243, 238, 228, 0.62);  /* secondary text, captions */
--ember:          #D9A05B;   /* THE accent. 2700K amber — the colour temperature of the product itself */
--ember-deep:     #A9743B;   /* hover/pressed state of ember only */
```

Accent discipline — this is non-negotiable:
- `--ember` may appear in at most **two places per viewport**: one primary CTA, and at most one micro-detail (an active state, a single rule, a focus ring). Nothing else. If a screen has ember in three places, remove one.
- Ember is never used as a background fill for large areas, never as a text colour for paragraphs, never in borders around images.
- The justification for this palette (state it in a code comment at the token definition): the amber is not a "brand colour" — it is the 2700K colour temperature of the product's own light. The UI stays monochrome so the lit photography carries all warmth.

### Typography tokens

Load from Google Fonts, `display=swap`, preconnect properly:

```
--font-display:  'Archivo', sans-serif;        /* headlines, wordmark, eyebrows */
--font-body:     'Instrument Sans', sans-serif; /* body copy, UI, forms */
--font-spec:     'IBM Plex Mono', monospace;    /* spec data, ratings, compliance labels, kit metadata */
```

Type rules:
- **Wordmark/eyebrows:** Archivo, weight 500, UPPERCASE, `letter-spacing: 0.14em`. Eyebrow labels ("The problem", "Environments", "Technical specification", "From the trade", "Enquire") get this treatment at ~12–13px, in `--bone-dim`.
- **H1/H2:** Archivo, weight 500 (never 700 — bold is trying to be heard; medium assumes it already has been), normal sentence case as currently written, `letter-spacing: -0.01em`, line-height 1.1–1.15. H1 clamps ~ `clamp(2.4rem, 5.5vw, 4.2rem)`; H2 ~ `clamp(1.8rem, 3.5vw, 2.6rem)`.
- **H3/card titles:** Archivo 500, ~1.25–1.4rem.
- **Body:** Instrument Sans 400, 16–17px, line-height 1.65, `--bone` for lead paragraphs, `--bone-dim` for supporting text. Max measure 68ch.
- **Spec/mono treatment:** every piece of technical data — "IP68", "0–10V", "RCM", "1.5m / 30 min", "EN60529", "24V", "20 business days", kit feature tags, the numbered markers 01/02/03 — is set in IBM Plex Mono, 12–13px, uppercase where short, `letter-spacing: 0.06em`, `--bone-dim`. This is the site's signature: spec data reads like an etched compliance plate. Apply it consistently — a reader should learn that mono = verifiable fact.
- No italics anywhere. Emphasis is achieved with `--bone` vs `--bone-dim` contrast or weight 500, never style.

### Space, radius, elevation

- Spacing scale: 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96 / 140px. Section vertical padding: 96–140px desktop, 64–80px mobile. The current site is competent; the rebrand should feel like the margins doubled. When in doubt, add space.
- `--radius: 2px` globally. Cards, buttons, inputs, images: 2px. Nothing pill-shaped, nothing above 4px. Sharp edges are part of the aluminium-extrusion language.
- Elevation: **no drop shadows.** Separation is achieved with `--ink` vs `--ink-raised` and 1px `--ink-line` borders only.
- Hairline rules (`1px solid var(--ink-line)`) may be used as section dividers and inside spec plates. They are the only decorative device permitted.

### Motion

- Permitted: opacity/transform fade-up on section entry (once, 300–450ms, ease-out, ≤12px travel), and background-colour/border transitions on hover (150ms). 
- Everything else: forbidden. All motion disabled under `prefers-reduced-motion`.

**Checklist:** all colours resolve to tokens; fonts loaded and applied per role; mono spec treatment applied site-wide; radius normalised to 2px; shadows removed; screenshot desktop + 360px.

## PHASE 4 — IMAGERY TREATMENT & SECTION EXECUTION

You cannot replace the photography (that happens outside this rebrand), but you can make the existing imagery read consistently:

1. **Unified image treatment:** apply a consistent CSS treatment to all content imagery: slight desaturation (`saturate(0.85)`), gentle contrast lift, and a subtle darkening overlay (`linear-gradient(rgba(15,17,19,0.15), rgba(15,17,19,0.35))`) so warm highlights read against a controlled base. Goal: every image looks like the same photographer at the same hour — deep dusk, warm 2700K light against dark structure.
2. **The green image problem:** the emerald-green cove image (`spec-cove-green`) breaks the single-colour-temperature rule. Swap its placement with the warmest existing dusk image in the asset set, or apply a stronger warm-bias treatment to it. Warm amber light is the brand; green is not.
3. **Environments grid:** keep the six cards. Card structure: image (2px radius, treated), H3 in Archivo 500, one-line bold claim, body in `--bone-dim`, "Read more" as secondary link. 1px `--ink-line` card borders on `--ink-raised`. Equal heights, generous internal padding (32px).
4. **Spec section ("Getting the fundamentals right"):** render each of the three specs as a "compliance plate": `--ink-raised` panel, 1px hairline border, the standard reference ("IEC 60529 · IP68", "0–10V Analogue Protocol", "Regulatory Compliance Mark") in the mono face top-left like an etched stamp, then title and body. This section should be the most visually distinctive on the page — it is the brand's proof, treated with the most care.
5. **Trade review section:** keep content and rating data. Fix presentation: the featured quote gets a large hairline-bordered panel, quote in Archivo 400/500 at ~1.3rem, attribution in mono. The four verified-delivery photos become a tight 4-up grid with the unified image treatment.
6. **Hero:** keep the current image and copy. Composition: full-bleed image with the darkening overlay strengthened at the bottom third, eyebrow in mono ("IP68 OUTDOOR LIGHTING · AUSTRALIAN CONDITIONS"), then the H1 wordmark treatment is NOT repeated in the hero — the H1 becomes the existing subhead line "Built for salt air, pool chemicals, and Queensland summers." elevated to H1 scale, with "IP68 end-to-end. Properly dimmable. Made for conditions that break everything else." beneath it. (The old hero repeated the brand name as the H1 under a nav that already says it — redundant. This restructure is permitted.)
7. **Dusk interstitials** ("Right about now." / "This is what it's for."): keep exactly as they are. These are the best moments on the site. Full-bleed, text bottom-left, mono eyebrow optional. Do not add anything to them.

**Checklist:** unified image treatment live; green image resolved; compliance plates built; hero restructured; screenshots desktop + mobile.
