## Stairs — is it actually width × count, or total metres + a decorative count?

The spec was "tread width × tread count, each tread its own run." The fields as built are called **Metres** and **Steps** — different naming, and possibly a different model. Here's what's making me check: the test shows stairs contributing exactly "8" to the total, labelled "8 steps" — which only equals 8 metres if each tread happens to be exactly 1m wide. That's either a coincidence in this test's input values, or a sign that "Metres" is being treated as one flat total for the whole staircase rather than a per-tread width that gets multiplied by count.

Why this actually matters, not just semantics: if it's one continuous run of `Metres` length, that's **not how stairs are physically built** — each tread is its own short run with its own connectors, sharing drivers via the same packing logic as everything else (that's the whole reason the spec called for it this way — it matches how Cody's and SWIMCO's real multi-run jobs actually ship). A single flat run would mean the wrong connector-set count on the BOM and a run-length model that doesn't match install reality, even if the total metres happens to look right in this one test.

Can you confirm directly: does the Stairs item generate **N separate runs of the tread-width value**, or **one run of the Metres value with Steps as a cosmetic label**? If it's the latter, that needs fixing before this checkpoint clears — not because the number's wrong today, but because it'll be wrong the moment someone enters a tread width that isn't coincidentally 1m.
